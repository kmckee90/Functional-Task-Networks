# Craftium input correction

Globo-Dreamer and `play.py --exact-parity` use the same corrected native engine.
The action list, mouse displacement, frame skipping (8), observation size,
game rules, and checkpoint action dimensions are unchanged.

The original Craftium 0.0.1 wheel held movement and DIG during skipped frames,
but cleared PLACE and SNEAK. Virtual input also omitted press/release events.
Consequently a short place action could never reach the placement callback,
and primary-use items could miss their use callback.

The patched engine holds PLACE/SNEAK across the existing native frame skip.
Each new policy command supplies one DIG/PLACE press event when requested,
and a release event when that button is no longer requested. Press events are
cleared after the engine handles the frame. Normal Luanti placement rules,
reach, inventory consumption, and callbacks remain in force.

This is an input-protocol change: historical absence of block placement cannot
be interpreted as a policy-learning failure. New environments record
`input_protocol.json` with version 2. Existing processes retain their loaded
engine until restarted. Checkpoints remain compatible.

## Build on a pod

`build_input_engine.py` downloads the Luanti 5.12.0 wheel-packaging revision
`da75c9b7f9c429c5f0b96e25ae29ed1f74b908f4`, applies the input patch, compiles it,
and installs under `$GLOBO_STATE/engines/input-v2/`. A manifest records the source
revision and binary SHA256. Source downloads and build artifacts stay outside
synced code. The original wheel binary is not overwritten.

Install build dependencies (Ubuntu) if needed:

```bash
apt-get update
apt-get install -y build-essential cmake ninja-build libpng-dev libjpeg-dev \
  libgl1-mesa-dev libsqlite3-dev libcurl4-openssl-dev libzstd-dev \
  libfreetype6-dev libluajit-5.1-dev libgmp-dev libsdl2-dev
/home/dev/globo_dreamer_state/venv/bin/python build_input_engine.py
```

`GLOBO_STATE` defaults to `/home/dev/globo_dreamer_state`. `BUILD_THREADS`
defaults to 8. `GLOBO_INPUT_BINARY` can explicitly select a compatible patched
binary. Missing builds fail with an explanatory error rather than silently
falling back to broken input handling.

Run the regression from the experiments directory:

```bash
/home/dev/globo_dreamer_state/venv/bin/python -m globo_dreamer.test_input_protocol
```

It uses `Globo.step()` in an isolated temporary world, selects a slot with one
command, issues one place action, checks a placement and inventory consumption,
then checks that one dig/use action invokes an item's primary-use callback once.

Validated on globo1: one `slot_2` command selected slot 2; one `place_use`
command placed `nodes_nature:silt_wet` and reduced its stack from 10 to 9.
One `dig_use` command invoked the test item's `on_use` exactly once.
The patched binary reports Luanti 5.12.0.
