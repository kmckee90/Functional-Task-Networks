# v2 — feature-complete FTN experiments

Copy of `base_rf` (the stand-alone refactor of `base/` in which the **FTN is
a single self-contained class** — backbone, task mask, and reconfiguration
loop all on `ftn.FTN`; `run_experiments.py` only optimizes weights and
decides *when* to reconfigure), extended with the up-to-date experiment
features:

- **Domain shift** (from `weight_freezing/`): `DOMAIN_SHIFT` +
  `DOMAIN_SHIFT_STRIDE` embed each task's `X_DIM` input in its own slice of a
  wider vector (stride 0 = concept shift, stride >= X_DIM = orthogonal
  supports); `DOMAIN_DENSE_PROJECTION` (+ `DOMAIN_PER_TASK_PROJECTION`)
  rotates the sparse inputs into a dense domain with fixed random orthogonal
  projection(s). The model input width follows automatically
  (`data_gen.total_input_dim`). The old additive `DOMAIN_SHIFT_FACTOR` remains.
- **Reconfiguration scheduling** (from `weight_freezing/`): `RECONFIG_EVERY`
  (per batch / every N batches / 0 = once per task block) and
  `RECONFIG_REACTIVE` (+ `_SD`, `_EMA`): boundary-free loss-triggered
  reconfiguration — once at the very start, then only when the batch loss
  exceeds the EMA mean by `_SD` standard deviations. Eval reconfigs never
  leak into training state (mask save/restore around evals).
- **Mask algorithm selection** (from `base/`, but living inside `FTN`):
  `MASK_LATERAL_STEPS = 0` = plain KWTA; `> 0` = SmoothKWTA with
  `MASK_KERNEL_SIZE`; `MASK_LATERAL_POLYAK` / `MASK_LATERAL_NOISE_SD` cover
  the Polyak/noisy variants.
- **Replay stays available** (`N_REPLAY_SAMPLES = 0` disables). **No weight
  freezing** — that mechanism lives in `weight_freezing/` only.
- `RENDER_STEPS = False` (config or `--render-steps 0`) skips per-step mask
  GIFs and task vis for speed; loss plots and transfer matrices always save.

The experiment is exactly the old **phase 1** (multi-task learning over the
task stream, with replay and the backwards/prospective forgetting monitor);
phases 0/2/3/4 were dropped as subsumed by it.

No file here imports from `base/`; the folder can be moved out or promoted to
replace `base/` as-is.

## FTN API

```python
ftn = FTN(input_size, output_size, hidden_size, square_dim, **Config.FTN_PARS)

pred = ftn(x, y)          # reconfigure mask on this batch, then predict
pred = ftn(x)             # predict with current mask (holdout eval)
pred = ftn(x, m=m_stored) # predict under an explicit mask (replay)
ftn.reconfigure(x, y)     # reconfigure only; result in ftn.m (buffer)
ftn.loss(pred, y)         # CE (one-hot) or MSE, per `classification`
big = ftn.expand(2 * ftn.hidden_size)  # neurogenesis (weights copied)
```

The weight optimizer stays outside the class (`AdamW(ftn.parameters())` in the
runner). `reconfigure()` detaches all weights, so mask optimization leaves no
gradients on FTN parameters.

## Simplifications vs base/

- **Phase 1 only** — pretraining, OOD continual learning, task-0 recovery, and
  neurogenesis phases removed (`PHASES` config gone). `FTN.expand()` is kept
  on the class as model capability, but the runner no longer uses it.
- **Per-batch reconfiguration always** — `CONFIGURE_PER_BATCH` is gone;
  `forward(x, y)` reconfigures.
- **One mask algorithm** — annealed-STE KWTA with optional lateral smoothing
  (the old `masks.SmoothKWTA`). `MASK_LATERAL_STEPS = 0` (the default config)
  reproduces the old `masks.KWTA`. All other configurers
  (DualKernel/GridCell/MexicanHat/Random/Disabled/KWTA_Search) dropped.
- **Replay**: `SHUFFLE_ON_REPLAY` removed (batches are subsampled to
  `REPLAY_BATCH_SIZE` rows once at store time). `REPLAY_BATCH_SIZE` kept.
- **Bug fix**: replay previously sampled `randint(0, len(overlap))` and used
  it as a *buffer* index; it now samples from the overlapping entries
  themselves (`overlap[choice]`).
- Only `NeuroModel`-style backbone and `DataGenSine` are ported (the active
  setup). One `TORUS` flag now governs both lateral convs (backbone lateral is
  disabled in the default config anyway).
- Task images are generated by calling `tasks.save_task_vis()` directly
  instead of a `subprocess` run of `tasks.py`.

Not ported (still old-API in base/): `vis_ftn.py`, `viz_latents*.py`,
the `MLP`/`MaskedMLP*`/`Spatial0` model variants, `DataGen` (softmax decoder),
and the `Regression*` configs.

## Run

```bash
python run_experiments.py                      # Default config
python run_experiments.py --config Smoke       # tiny end-to-end sanity check
python run_experiments.py --config Default DomainShift NoReplay  # combine; last wins conflicts
python run_experiments.py --name run1          # outputs in artifacts/run1/
python run_experiments.py --render-steps 0     # skip per-step GIFs / task vis
python run_experiments.py --reconfig-every 0   # reconfig once per task block
```

With `--name run1`, outputs land in `artifacts/run1/` as `bw_run1.gif`,
`rgb_run1.{png,gif}`, `loss_run1.png`, `xfer_run1.png`, `task_vis_run1.png`,
plus `config_run1.txt` — a dump of every effective config value
(post-composition, post-CLI-overrides) and the command line, so each run
directory is self-describing. Per-run directory, but filenames stay suffixed
so runs can be pooled into one folder later. Without `--name`, files go to
`artifacts/` unsuffixed (`bw.gif`, `loss.png`, …). The old `p1_mtl` filename
prefix is gone.
